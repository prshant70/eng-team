The Core Thesis

In agentic systems, code is not only output — it is the operational harness.

The survey argues that code is the executable substrate for reasoning, acting, environment modeling, and verification. A good harness makes behavior executable, inspectable, stateful, and verifiable over long horizons. Progress depends as much on harness engineering (tools, memory, oracles, control loops, multi-agent shared state) as on the base model.

The harness interface is how agents read and write state: CLAUDE.md for conventions, technical_spec for the plan artifact, Engineer edits for implementation, and Reviewer git diff for output-based judgment. Aligns with PHILOSOPHY.md — bottom-up trust, narrow insertion point, diff over intent.

The article does not suggest replacing this design. It names what to harden next: oracle quality, shared state discipline, harness telemetry, and governed iteration.

8 Key Upgrades

Article recommendations mapped to concrete eng-team changes. Select an upgrade to explore.

Scratchpad as Program State §2.3, §4.2, §5.2.4

Extend .eng_team/task_*.json beyond narrative logging:

  • verification_evidence — tests run, linter result, diff stats
  • assumptions[] with verified_by (test / diff hunk / reviewer item)
  • Per-phase read_set / write_set
  • Commit pins: base_commit, spec_version, impl_commit

Transactional shared program state — the scratchpad becomes executable harness memory, not just a log.

Verification Stack §5.2.1–5.2.2

On approve, require an evidence bundle — not only "tests passed":

  • What was checked (unit / integration / security hints / coverage on touched files)
  • untested_regions[] — what the oracle does not prove
  • For complex tasks: runnable acceptance_checks or test skeletons in the spec

Oracle adequacy and semantic verification beyond executable feedback.

Harness-Level Evaluation §5.2.1

Log per-run trajectory metrics in the scratchpad:

  • Phase durations, clarification/review cycles
  • Recovery: each critical_issue linked to a fix commit
  • oracle_strength (trivial vs full checklist, targeted re-review scope)

Evaluate the harness, not only final task success.

Failure-Type Routing §3.4

Route feedback by signal type in the orchestrator — see the interactive routing section below.

  • spec_gaps → Tech Lead (max 1 cycle)
  • Test failure → Engineer fix mode
  • Lint only → Engineer, narrow scope
  • Behavior vs spec → Tech Lead, not blind Engineer patch
  • Security/perf → Reviewer targeted re-review

Plan → execute → verify with feedback-driven control.

Action Validation §2.2

Pre-flight before Engineer acts — lightweight harness boundary:

  • Edits only under files_to_modify / files_to_create
  • No edits on base_branch
  • Bash allowlist from CLAUDE.md (no destructive or secret-leaking commands)

Code mediates intent; filter invalid actions before execution.

Human Gates as Durable State §5.2.5

Scratchpad fields for human decisions that persist across runs:

  • human_gates — prd_approved, spec_approved, merge_approved
  • human_resolution on escalation so later runs do not repeat the same failure

The gate that stays human — per PHILOSOPHY.md.

Cross-Task Memory §3.2

Optional, later — governed institutional memory:

  • .eng_team/learnings.json for recurring reviewer findings
  • Flaky areas, repo-specific patterns — opt-in, governed

Memory and context engineering across tasks.

Harness Evolution with Regression Discipline §5.2.3

Self-evolving harnesses without regression:

  • Golden fixture repos + expected scratchpad phases
  • Prompt/checklist changes only with held-out regression tasks
  • Explicit change contracts for harness modifications

Harness failures improve the system — with regression discipline.

Bottom Line

eng-team is already a code-as-harness system for software engineering. The survey's main push is to evolve from prompt orchestration that usually works to harness engineering: every approval carries proof, every phase carries versioned assumptions, and harness failures improve the system with regression discipline — without widening scope beyond the PRD → PR slice until trust is earned.
